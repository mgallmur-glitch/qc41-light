# Intellectual Property Boundary

QC 4.1 Light is intentionally useful but bounded.

## Public-safe layer

- transcript facts;
- exact evidence excerpts;
- generic sales-call stages;
- most likely breakpoint;
- explicit and cautiously inferred objections;
- observable mistakes;
- concrete corrections;
- one recovery line;
- next-call focus;
- confidence and limitations.

## Private QC 4.1 layer

The following must not appear in this repository, examples, adapters, issues, docs or generated reports:

- proprietary profile names or taxonomies;
- proprietary depth or diagnostic levels;
- internal objection or closing-system names;
- scoring dimensions, weights, formulas or verdict logic;
- internal prompt corpus and few-shot examples;
- system-selection mappings;
- team benchmarking;
- longitudinal coaching logic;
- internal glossary;
- production API internals;
- customer data or real transcripts without authorization.

## Language guard

Use generic public terms such as:

- buyer behavior;
- decision process;
- stated objection;
- underlying concern;
- diagnosis depth;
- breakpoint;
- recovery line;
- call evidence.

Do not translate proprietary names into thinly disguised synonyms that preserve the underlying mapping.

## Upgrade boundary

A paid layer is justified by depth and continuity, not by making Light useless:

- complete methodology;
- professional forensic review;
- team comparison;
- batch processing;
- history;
- dashboards;
- coaching;
- managed infrastructure;
- integrations and support.

## Release gate

Before any public push:

1. Search the entire repository for prohibited internal terminology.
2. Review prompt and examples manually.
3. Confirm all transcripts are synthetic or authorized.
4. Confirm no endpoint, key, customer identifier or internal path is present.
5. Run tests and an adversarial IP-leak review.
6. Require Mauricio's explicit approval to publish.
